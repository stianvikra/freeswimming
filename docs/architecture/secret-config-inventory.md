# Secret And Config Inventory

## Purpose

This is the canonical repo inventory for active secret and runtime-config families in
Freeswimming. It names ownership, storage boundaries, sensitivity, rotation cadence, failure mode,
and non-secret verification evidence.

Use this inventory before adding, renaming, rotating, or deleting any environment variable,
provider credential, CI secret, control-plane token, or local-only bypass credential.

Related contracts:

- environment placement and smoke flow: `docs/runbooks/environment-config-and-secret-parity.md`
- external service behavior: `docs/architecture/external-service-contract-matrix.md`
- rotation checklist: `docs/checklists/admin-access-and-secret-rotation.md`
- private gate operations: `docs/runbooks/private-access-gate.md`
- Supabase egress guardrails: `docs/runbooks/supabase-egress-response.md`

## Inventory Rules

- Never store secret values in git, screenshots, PR comments, task briefs, or support notes.
- Treat `.env.local` as local-only and unsafe to quote.
- Vercel Preview and Production values are control-plane-canonical; changing them requires a new
  deployment before runtime behavior changes.
- GitHub Actions secrets are CI-canonical and must not be mirrored into Vercel unless the family
  explicitly says so.
- A family name is stable identity. If a credential is repurposed for materially different behavior,
  create a new family entry instead of overloading the existing one.
- Verification evidence must be limited to variable presence, selected environment scope,
  deployment ID, route status, redacted log class, or test result.

## Sensitivity Classes

| Class               | Meaning                                                                                  | Storage expectation                                                                                   |
| ------------------- | ---------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `public-runtime`    | Public config that can be bundled or exposed, but still controls app behavior.           | Repo docs may name keys; values live in local/Vercel/CI as needed.                                    |
| `server-config`     | Non-secret server value that can still affect security, delivery, redirects, or billing. | Local/Vercel/CI by environment; avoid casual public disclosure when it names internal addresses.      |
| `server-secret`     | Credential, token, password, webhook secret, service-role key, or provider API key.      | Server-only local/Vercel/GitHub/control plane. Never browser-exposed.                                 |
| `local-test-config` | Non-secret local or CI test setting that should not become deployed runtime config.      | `.env.local`, local shell, or GitHub CI only.                                                         |
| `local-only-secret` | Developer or Playwright helper credential that must not reach Preview or Production.     | `.env.local`, local shell, or GitHub CI when explicitly CI-scoped.                                    |
| `ops-safety-config` | Guardrail flag/marker used to prevent wrong-environment usage or accidental prod egress. | Local/CI/Preview/Production as documented; values should be non-secret but still change-controlled.   |
| `platform-provided` | Injected by Vercel, GitHub, or the runtime platform.                                     | Do not set manually unless the platform documentation requires it for a specific local/debug command. |

## Upstash Repair Readiness

Official baseline checked on `2026-05-07`:

- Upstash Redis REST calls use the database HTTPS REST URL plus `Authorization: Bearer <token>`.
- Upstash REST `401` means authentication failed because the token is missing or invalid.
- Upstash Standard tokens are full-privilege database credentials and must not be exposed publicly.
- Vercel environment variable changes apply only to new deployments, so repairing Preview or
  Production requires redeploying the affected environment before smoke evidence is meaningful.

Repair gate before broader public launch or higher-volume intake:

1. In the Upstash console, copy the correct Redis REST HTTPS URL and Standard token for the intended
   rate-limit database.
2. In Vercel, set `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN` in the affected
   Preview/Production scope without copying values into repo artifacts.
3. Redeploy the affected environment.
4. Run bounded smoke against one rate-limited route (`/api/contact`, `/api/download/resend`, or
   sign-in request path) and inspect logs for:
   - no Upstash `401`,
   - no app `500`,
   - expected route outcome,
   - no URL/token/IP/email/cookie/header values in logs.
5. Record only non-sensitive result evidence in `docs/checklists/admin-access-and-secret-rotation.md`
   or the active task brief.
6. If smoke fails, unset the pair to force in-memory fallback, redeploy, and record rollback status.

## Add Or Change A Family

Before adding or changing a family:

1. Add or update the row in this inventory.
2. Update `docs/runbooks/environment-config-and-secret-parity.md` if environment placement changes.
3. Update `docs/architecture/external-service-contract-matrix.md` if provider behavior, retries,
   diagnostics, idempotency, cost, or rollback changes.
4. Add or update the cheapest relevant test or smoke evidence for changed runtime behavior.
5. Record owner, rotation cadence, and failure mode in the active task brief before implementation.
